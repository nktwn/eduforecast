# EduForecast-SIS

Система аналитики и прогнозов для руководства вуза: одно Streamlit-приложение с командным центром, направлениями и ИИ-советником.

| направление | что есть | статус |
|---|---|---|
| Академическое | риск отчисления на неделе k (5/10/20) вне обучающей выборки, качество модели, факторы риска | демо: открытый набор OULAD, факультеты условные |
| Научное | публикации AITU (OpenAlex), модели роста против naive на панели вузов Казахстана | проверено; прогноз AITU — иллюстрация |
| Финансы | вузы США (IPEDS): прогноз 4 показателей с проверкой по критерию, бенчмарк структуры расходов, связь бюджета и результатов; профиль AITU 2019–2020 | проверено; основная модель критерий не прошла; данные США, контекст другой |
| Международное, воспитательное | только описание и список нужных данных | нет данных (концепция) |

**ИИ-советник** отвечает только числами из **реестра фактов**. У каждого факта есть статус (проверено / исследовательское / демо / нет данных), источник и оговорка. Без ключа LLM советник работает в режиме брифинга по роли.

## Установка и запуск

Нужен Python 3.12. Версии библиотек закреплены в `requirements.txt`: на них проверены приложение и тесты; на более новых Streamlit часть оформления может не применяться.

```bash
git clone <url-репозитория> eduforecast
cd eduforecast
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # для приложения и тестов достаточно requirements-ci.txt
streamlit run app/main.py
```

Приложение откроется на <http://localhost:8501>.
- **Работает сразу**, без данных: Командный центр, ИИ-советник (брифинг), «Что проверено», «Настройки», Научный, профиль AITU, концепции «Международный» и «Воспитательный». Реестр фактов лежит в репозитории (`src/advisor/facts/snapshot.json`).
- **Academic и Finance** показывают «Данные не найдены» до подготовки данных (раздел ниже). Finance без данных открывается в мок-режиме.
- **Быстрое открытие страниц.** После подготовки данных выполните `python scripts/prepare_app.py` (2–3 мин). Скрипт один раз считает модель риска для всех недель и факультетов и прогноз Prophet в `data/app_cache/`; страницы открываются за 0–3 с вместо 5–25 с. Без этого шага всё работает, но первая загрузка Academic медленнее.

### Переменные окружения

Задаются в `.env` в корне или в `.streamlit/secrets.toml`; оба файла в `.gitignore`.

| переменная | назначение | по умолчанию |
|---|---|---|
| `GROQ_API_KEY` или `ADVISOR_API_KEY` | ключ LLM | — (без ключа — брифинг без LLM) |
| `ADVISOR_MODEL` | модель | `openai/gpt-oss-120b` |
| `ADVISOR_BASE_URL` | OpenAI-совместимый endpoint (Groq или другой провайдер) | `https://api.groq.com/openai/v1` |
| `ADVISOR_TIMEOUT` | таймаут запроса, с | `30` |
| `OPENALEX_MAILTO` | e-mail для OpenAlex (только пересборка панели Research) | — |
| `OPENALEX_API_KEY` | ключ OpenAlex (пересборка панели этапа 3: 10 000 кредитов в день вместо 1 000); в логи и отчёты не выводится | — |

### Режимы

- **С ключом** — советник отвечает на свободные вопросы с инструментами (function calling). Если вызов инструментов недоступен, советник получает в контексте сводку фактов.
- **Без ключа** — брифинг по роли из шаблонов и фактов. Страница «Настройки» показывает статус ключа: нет / есть / недействителен.
- **Без данных** — страницы показывают пустые состояния и подсказки; Finance — мок-режим.
- **Темы** — светлая и тёмная (меню ⋮ → Settings или системная тема), контраст не ниже WCAG AA.

## Подготовка данных

Все команды выполняются из корня проекта с активированным `.venv`. Данные в git не хранятся, кроме копии OpenAlex для Research.

### Academic (OULAD)

Открытый набор Open University Learning Analytics Dataset (Open University, UK) — 7 CSV-файлов, около 460 МБ после распаковки. Загрузка и распаковка занимают около минуты.

```bash
mkdir -p data/raw
curl -L -o /tmp/oulad.zip "https://archive.ics.uci.edu/static/public/349/open+university+learning+analytics+dataset.zip"
unzip -o -j /tmp/oulad.zip "*.csv" -d data/raw
```

Должны появиться `studentInfo.csv`, `studentVle.csv`, `studentAssessment.csv`, `assessments.csv`, `studentRegistration.csv`, `courses.csv`, `vle.csv`. Первоисточник набора — <https://analyse.kmi.open.ac.uk/open_dataset>; там файлы нужно скачать вручную через браузер. Подробности — в [data/README.md](data/README.md).

При первом открытии страницы Academic модель риска обучается заново, это занимает 5–30 секунд в зависимости от факультета.

### Finance (IPEDS)

Данные NCES IPEDS 2010–2023 и индекс цен CPI-U (FRED) скачиваются автоматически:

```bash
python -m src.finance.download         # ~2.3 ГБ, 207 файлов (с этапом 2), 15–30 минут (зависит от сети)
python -m src.finance.panel            # панель вуз × год → data/finance/panel.parquet, ~1 минута
python -m src.finance.api.demo_model   # демо-модели LightGBM → data/finance/models/, ~1 минута
python -m src.finance.panel_stage2     # + приём, помощь, цены, кадры, программы, натуральные статьи, ~40 с
python -m src.finance.models_stage2 rolling && python -m src.finance.models_stage2 unseen   # ~10–20 минут
python -m src.finance.models_stage2 report && python -m src.finance.models_stage2 deploy
python -m src.finance.budget_outcomes  # связь структуры бюджета и результатов (H1–H4)
```

Полный список команд этапа 2 и время — [FINANCE_STAGE2_REPORT.md](FINANCE_STAGE2_REPORT.md), §10. Профиль AITU (`data/aitu/`) лежит в репозитории и показывается без данных IPEDS.

Загрузка кэширует файлы на диск: при обрыве повторный запуск докачает только недостающее. Проверить, что прогноз собирается по контракту API:

```bash
python -m src.finance.api.cli "UCLA"
```

### Research (OpenAlex)

Ничего делать не нужно: копия ответа OpenAlex лежит в `data/research/raw/yearly_work_counts_I4405257690.json`, и страница работает без сети.

Результаты панели 50 вузов (этап 3) страница берёт из реестра фактов `src/advisor/facts/snapshot.json`, который лежит в репозитории.

Пересборка данных Research тянет их из OpenAlex:
- панель 14 вузов этапа 2 — `python -m src.research.panel`; упирается в бесплатный дневной лимит (1 000 кредитов), нужен `OPENALEX_MAILTO`;
- панель 50 вузов этапа 3 — около 1 750 кредитов, нужен `OPENALEX_API_KEY` в `.env`. Команды:

```bash
python -m src.research.candidates       # отбор вузов по зафиксированным правилам
python -m src.research.panel_stage3     # панель 2010–2025 (дисковый кэш, продолжение после обрыва)
python -m src.research.audit_stage3     # аудит: пропуски, разрывы, выбросы, дубли аффилиаций
python -m src.research.stage3 run       # модели, ~3 минуты
python -m src.research.stage3 report    # критерии C1/C2, конформные интервалы, SHAP, AITU
python -m src.advisor.facts.registry    # обновить реестр фактов
```

OpenAlex меняет данные задним числом, поэтому числа воспроизводимы только с той же выгрузкой.

## Как пользоваться

Выберите роль в боковой панели или на Командном центре: ректор или один из проректоров (академическая работа, наука и инновации, экономика и финансы, интернационализация, цифровизация). Роль задаёт показатели на главной, инструменты советника и быстрые вопросы.

**Разделы навигации:**
- **Командный центр** — ключевые показатели роли с бейджами статуса, светофор готовности модулей, «Что требует внимания» (из реестра фактов), быстрые вопросы советнику.
- **Направления:**
  - **Академический: обзор / студенты / аналитика** — сводка условного факультета; риск отчисления на неделе k с качеством модели (AUC, precision и охват в топ-10%, Brier, калибровка); список студентов с главной причиной (только здесь, советник его не видит); сравнение факультетов.
  - **Научный** — публикации AITU и прогноз Prophet с бэктестом (иллюстрация).
  - **Финансы** — прогноз вуза США со статусом критерия, качество моделей, профиль AITU (снимок 2020 года), связь бюджета и результатов («связь, не причина»).
  - **Международный, Воспитательный** — концепции: описание и список данных, которые нужно собрать; без чисел.
- **Советник и методика:**
  - **ИИ-советник** — «Брифинг по роли» (карточки, выгрузка в Markdown и печатный HTML) и «Вопросы» (чат с потоковым выводом и панелью «Основания»).
  - **Что проверено** — статусы модулей, матрица «умеет / не умеет», ключевые метрики, отчёты аудита, поиск по реестру фактов.
  - **Настройки и состояние** — ключ, модель, данные, версии, время сборки реестра.

На каждой странице направления есть блок «Как читать эту страницу»: что показывает, как читать, результат, проверка, оговорки.

## Как работает советник

1. **Реестр фактов** (`src/advisor/facts/`) читает сохранённые результаты аудитов и моделей, ничего не пересчитывая.
   - У каждого факта есть id, модуль, показатель, значение, единицы, период, статус, источник (путь к файлу), оговорка и время сборки.
   - Снимок `snapshot.json` содержит только агрегаты; пересобирается командой `python -m src.advisor.facts.registry`.
2. **Инструменты** (`src/advisor/tools.py`) отдают модели факты с плейсхолдерами `{fact:ID}`. Набор инструментов зависит от роли (`src/advisor/roles.py`).
3. **Ответ модели** — JSON: наблюдение → основание (id фактов) → рекомендация → риски и ограничения.
   - Числа пишутся только плейсхолдерами, подставляет их код; надёжность ответа равна статусу самого слабого факта.
   - Неизвестный плейсхолдер, факт, не полученный в этом запросе, «голое» число или причинная формулировка («эффект», «приведёт») ведут к одному повторному запросу. Если и он не проходит проверку, пользователь видит честное сообщение об ошибке, а не неподтверждённый ответ.
4. **Без LLM** (`src/advisor/guard.py`) обрабатываются вопросы:
   - о конкретных студентах и группах меньше 30;
   - о направлениях без данных: ответ «нет данных» и что собрать;
   - о бюджете в процентах: только описательные ориентиры.
5. **Журнал** `logs/advisor_queries.jsonl` (в `.gitignore`) — вопрос с замаскированными номерами и e-mail, инструменты, результат проверки; без ключей.
6. **20 контрольных вопросов** (`src/advisor/control_questions.py`) проверяются тестами со сценарной заглушкой и живым прогоном `python scripts/run_control_questions.py`.

## Как добавить модуль и факты

1. **Сохранить результаты модуля в файлы** (CSV или JSON в `results/<модуль>/`). Советник читает только сохранённые результаты.
2. **Добавить сборщик в `src/advisor/facts/builders.py`** и включить его в `BUILDERS` в `registry.py`.
   - Каждый факт получает статус, источник и оговорку.
   - Если файла нет, факт получает статус «нет данных».
3. **Добавить в `CAPABILITIES` и `NEEDED_DATA`** (там же), что направление умеет, чего не умеет и какие данные нужны.
4. **Добавить инструмент в `src/advisor/tools.py`** (функция + описание в `SCHEMAS`) и открыть его нужным ролям в `roles.py`.
5. **Пересобрать реестр** (`python -m src.advisor.facts.registry`) и запустить `pytest`: тесты проверяют схему фактов, наличие источников и совпадение значений с файлами.
6. **Добавить страницу** в `app/pages/` и в `PAGES` в `app/main.py`. Для оформления используйте компоненты `app/components/ui.py`: заголовок со статусом, KPI-карточка, оговорка, «Как читать».

## Что в бете демо или мок

- **Academic — демо-данные.** Это открытый набор OULAD (Open University, UK), а названия «факультетов» условные. Модель риска видит только данные недель ≤ k и оценена вне обучающей выборки; AUC на неделе 5 умеренный (около 0,70). Аудит исследовательской части — [ACADEMIC_AUDIT.md](ACADEMIC_AUDIT.md).
- **Аналитика.** Бенчмарки («Мировой топ-100», «Цель AIU» и др.) заданы вручную для иллюстрации. «Удержание студентов» — линейная экстраполяция, а не модель. Если API Всемирного банка недоступен, показываются справочные значения с пометкой.
- **Научная продуктивность.**
  - Панель 50 вузов, критерии зафиксированы до запуска. Модели лучше naive для счётчиков (публикации, авторы, цитирования, международные связи), но не для долей.
  - Лучше простого среднего роста панели и возрастной группы — ни для одного показателя (критерий C2).
  - Прогноз AITU на 2026 строится только для показателей, прошедших C1, и помечен «исследовательское».
  - Процентили AITU — описательный бенчмарк, не причинность.
  - Prophet по ряду AITU — прежняя иллюстрация на 6 годовых точках; потолок логистической модели — экспертная оценка.
- **Финансы.**
  - Данные США (IPEDS), контекст другой.
  - Модель этапа 2 (LightGBM S3) оценена по зафиксированному критерию и **не прошла его ни по одной из четырёх целей**: лучше naive на 2–10%, а нужно не меньше 10% в обеих оценках. Страница показывает статус по каждой цели.
  - Демо-модель оставлена как отдельный режим и по критерию не оценивалась.
  - Связь структуры бюджета и результатов — описательная, не причинная. Гипотезы H1–H4 не подтвердились.
  - Профиль AITU — два года (2019–2020) из отсканированной отчётности, `verified=false`.
  - Режим «Мок» полностью синтетический.
  - HTTP API нет: контракт `finance-forecast/0.2.0` описан, но страница вызывает провайдер напрямую.

  Подробно — [FINANCE_STAGE2_REPORT.md](FINANCE_STAGE2_REPORT.md) и [FINANCE_BETA.md](FINANCE_BETA.md), §4.

## DevOps: Docker and Jenkins CI/CD

Docker image, local Jenkins (configured as code) and a pipeline that lints, runs the unit tests, builds and smoke-tests the image, optionally pushes it and deploys a test container on http://localhost:8502. Details: [docs/devops/](docs/devops/README.md) (runbook, evidence, screenshots).

```bash
make docker-test     # tests in the container
make docker-build    # runtime image eduforecast:dev (no data, no secrets, non-root)
make jenkins-up      # Jenkins on http://localhost:8080; admin password in jenkins/.env.jenkins
```

New environment variables (names only; values in the git-ignored `jenkins/.env.jenkins`, template `jenkins/.env.jenkins.example`): `JENKINS_ADMIN_ID`, `JENKINS_ADMIN_PASSWORD`, `GIT_REPO_URL`, `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`. Application variables are listed in `.env.example`.
